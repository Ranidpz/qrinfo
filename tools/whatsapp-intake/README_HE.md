# The Q — איסוף חוברות מ־WhatsApp למק

גרסת פיילוט 0.2.0. תוכנה מקומית עצמאית: Playwright פותח פרופיל WhatsApp Web עסקי ייעודי, מוריד PDF מהקבוצה שהוגדרה ומעביר אותם ל־API של The Q. אין צורך להתקין Codex, מנוי ChatGPT או מפתח OpenAI במחשב המפעיל.

## התקנה ראשונה אצל מיכל

1. מתקינים Node.js LTS מ־https://nodejs.org/en/download אם אינו מותקן.
2. מחלצים את החבילה לתיקייה ומפעילים `Install.command`. ההתקנה מורידה תלויות ודפדפן תואם למק המקומי, ולכן דורשת אינטרנט.
3. פותחים ב־Finder את `~/Library/Application Support/TheQContentIntake/Commands`.
4. מפעילים `Connect.command`, סורקים בטלפון של **חשבון המשרד**, ומוודאים שמופיעה הקבוצה **חוברות QR פתאל**. ממתינים לסיום סנכרון ההיסטוריה, ואז סוגרים את החלון.
5. מפעילים `ConfirmBusinessAccount.command` ומאשרים שזה החשבון העסקי הנכון.
6. מפעילים `SetApiKey.command` ומדביקים את מפתח האינטגרציה שנמסר. ההקלדה מוסתרת; המפתח נשמר מקומית בהרשאות קריאה למשתמש בלבד. אין להדביקו בצ׳אט או לשלוח עם החבילה.
7. מפעילים `Collect.command` לבדיקת הורדה בלבד, ואחריו `Preview.command` לבדיקת ההתאמות בשרת.
8. רק לאחר בדיקת הדוח והפעלת גרסת השרת המתאימה, מפעילים `Update.command` לניסוי החלפה אמיתי. המערכת דורשת `batchProtocolVersion: 1`; שרת ישן נעצר לפני העלאת PDF.

הפרופיל הייעודי אינו משתמש בדפדפן הפרטי או באפליקציית WhatsApp הרגילה. אפשר להשאיר אצל מיכל את המשרד באפליקציה ואת הפרטי בווב. סגירת החלון אינה יציאה מהחשבון. ניתוק דרך הטלפון, מחיקת נתוני הפרופיל או פקיעת החיבור יחייבו קישור חוזר.

זו חבילת קוד להתקנה, לא אפליקציה חתומה ומאושרת להפצה מסחרית. אם macOS חוסם את הקובץ שהורד, בודקים את מקור החבילה ופותחים דרך הגדרות פרטיות ואבטחה; אין לבטל את Gatekeeper או להפעיל `sudo` לצורך ההתקנה.

## זמנים ומצב הפעלה

ההגדרות נמצאות ב־`~/Library/Application Support/TheQContentIntake/config.json`:

- ברירת המחדל: ראשון וחמישי, 10:05, 12:00 ו־14:00, לפי `Asia/Jerusalem` כולל שעון קיץ.
- חלון איסוף של 36 שעות כולל את החוברות שנשלחות בערב הקודם. ניתן לשנות `scanWindowHours`; הגבול העליון `scanLookbackHours` הוא 96 שעות.
- `schedule.enabled: false` ו־`autoCommit: false` בהתקנה חדשה. אין החלפות אוטומטיות לפני השלמת הפיילוט.
- `dateOrder` חייב להתאים לתאריך שמציג חשבון WhatsApp. בחשבון שנבדק הוא `MDY` (9/20/2026), אף שהודעות הקבוצה בעברית.

לאחר ניסוי מוצלח מפעילים תזמון בדיקה דרך Terminal:

```sh
node "$HOME/Library/Application Support/TheQContentIntake/app/src/macos.mjs" --activate
```

כדי לאפשר גם החלפה אוטומטית משנים `autoCommit` ל־`true` בקובץ ההגדרות **לאחר אימות ההחלפה והדוח**. לעצירה:

```sh
node "$HOME/Library/Application Support/TheQContentIntake/app/src/macos.mjs" --disable
```

LaunchAgent בודק כל חמש דקות אם הגיע חלון הרצה. התעוררות באותו יום משלימה רק את המועד האחרון שהוחמץ. אין השלמה אוטומטית של ימים קודמים. המשתמש צריך להיות מחובר למק; לאחר כיבוי והפעלה יש להיכנס לחשבון macOS.

## הגדרות המק מיני

בהגדרות המערכת → אנרגיה, מפעילים **מניעת שינה אוטומטית כאשר הצג כבוי**. שמות ומיקום האפשרות משתנים מעט בין גרסאות macOS. מותר לכבות את הצג ולנעול את המסך. יש להשאיר את המק דולק, מחובר לאינטרנט ובחשבון המשתמש שבו הותקנה התוכנה. אין צורך לבטל נעילת מסך, FileVault או לדרוש כניסה אוטומטית.

בזמן איסוף התוכנה מפעילה `caffeinate` למניעת שינה באמצע ההרצה; הוא אינו מעיר מחשב שכבר ישן. `Status.command` מציג את הגדרות החשמל, מצב הנעילה ובדיקת API מוגבלת למיפוי 12 החוברות. אם מופיע `ownerMatches: false`, יש לברר את חשבון הבעלים לפני שינוי ההרשאה; אין להרחיב את המפתח לכל המערכת. המתקין אינו משנה את הגדרות השינה של המחשב באופן גורף.

מקור Apple: https://support.apple.com/guide/mac-help/set-sleep-and-wake-settings-mchle41a6ccd/mac

## דוחות ותקלות

הנתונים נשמרים ב־`~/Library/Application Support/TheQContentIntake/fattal-playzone/`:

| קובץ | שימוש |
|---|---|
| `status.json` | מצב ההרצה האחרונה |
| `last-collection.json` | שמות הקבצים, זמני קבלה ונתיבי PDF |
| `last-preview.json` | התאמה למלונות וחוסרים לפני החלפה |
| `last-report.json` | תוצאות מאושרות מהשרת |
| `outbox/` | הודעות לקבוצה ואישורי שליחה, למניעת כפילויות |
| `checkpoint.json` | הקבצים שכבר טופלו באותו יום |
| `pending.json` | הרצה שלא אושרה עד סופה; מונעת כתיבה חוזרת עיוורת |
| `messages.json` | יומן הורדות עם מזהי הודעות וגיבובי SHA-256 |
| `downloads/` | קבצי המקור; נשמרים לבקרה |
| `browser/` | פרופיל ההתחברות; פרטי ואין להעבירו ללקוחות |

השרת שולח דוח עדכון ל־`info@playzone.co.il` באמצעות Resend. במק נדרש רק מפתח האינטגרציה. `/agent-status` מדווח על ניתוק, תקלה, חוסר קבצים וחזרה לתקינות, ומדכא התראות חוזרות כשהמצב לא השתנה. כשאין אינטרנט או כשהמק כבוי אין אפשרות לשלוח התראה בזמן אמת; נדרש ניטור חיצוני כדי לזהות מחשב שאינו פועל.

`sendGroupReports: true` מפעיל דיווח לקבוצה העסקית לאחר הרשאה מפורשת של הלקוח. בפעימה הראשונה ההודעה מסכמת מה התקבל, מה עודכן ומה חסר. בבדיקות 12:00 ו־14:00 מודיעים רק אם עלו חוברות נוספות; ללא קובץ חדש אין החלפה או הודעה חוזרת. ברירת המחדל בחבילה ללקוח חדש כבויה. נשמרת תיבת הודעות יוצאות לפני השליחה, ושליחה לא ודאית אינה נשלחת שוב אוטומטית.

- `LOGIN_REQUIRED`: מפעילים שוב Connect. סריקה נדרשת רק אם מוצג QR.
- `FILES_NEED_REVIEW`: לא הוחלף דבר; בודקים התאמות/שמות כפולים בדוח. אין בחירה אוטומטית בין חוברות מתחרות לאותו מלון.
- `HISTORY_BOUNDARY_NOT_VERIFIED`: לא הוכח שההיסטוריה נטענה עד תחילת החלון. ממתינים לסנכרון ב־Connect ומנסים שוב. לא מעלים אוסף חלקי כאילו הוא מלא.
- `UNCONFIRMED_BATCH`: מפעילים `ResumeReport.command` כדי לברר את תוצאות ההרצה הקודמת. פקודה זו אינה שולחת שוב את הקבצים. אם הדוח חלקי, איש תמיכה צריך לבדוק לפני שחרור ההרצה.
- אחרי קריסה, `UnlockAfterCrash.command` מסיר נעילה רק אם התהליך שרשום בה כבר אינו קיים. אין למחוק נעילה של תהליך פעיל.

## תחזוקה ולקוחות נוספים

זה מחבר ממשק דפדפן, לא WhatsApp Business API רשמי. שינוי בממשק עשוי לדרוש עדכון המחבר. הפרדת הקוד מאפשרת להחליף את מקור האיסוף בלי לשנות את כללי התאמת המלונות. כל התקנת לקוח צריכה פרופיל עסקי משלה, הגדרות קבוצה, מיפוי יעדים ומפתח מוגבל לבעלים המתאים בצד השרת. שינוי `ownerEmail` במק לבדו אינו מעניק הרשאה ללקוח נוסף.

החבילה אינה כוללת פרופילים, סיסמאות, קבצים עסקיים או מפתחות. אין להעביר למיכל את תיקיית Application Support של רני. יש לסרוק בנפרד במחשב שלה. יש להפעיל את התזמון במחשב אחד בלבד לכל אינטגרציה.

בדיקות פיתוח:

```sh
npm ci
npx playwright install chromium
npm test
```

בדיקות אלה כוללות הורדה בדפדפן מול דף בדיקה מקומי; בנוסף נדרש ניסוי חי מול הקבוצה, ה־API והדוח לפני הפעלה אוטומטית. תיעוד Playwright: https://playwright.dev/docs/downloads

## חיבור מהדשבורד (גרסה 0.4.0)

במערכת בחרו ״עדכון חוברות״. בעל החוברות או מנהל־על יכולים ליצור מפתח אישי למחשב ולבטל אותו. המפתח מאפשר עדכון רק לחוברות פתאל הממופות של הבעלים שנבחר; השרת שומר גיבוב בלבד.

הורידו את קובץ `TheQ-connection.json` ושמרו אותו ליד `Install.command` לפני ההתקנה. בהתקנה חדשה הוא מיובא אוטומטית; בהתקנה קיימת משתמשים ב־`ImportConnection.command`. הייבוא משבית את התזמון ומחזיר למצב בדיקה. שמרו את קובץ החיבור במקום פרטי, ואל תעבירו אותו עם חבילת התוכנה ללקוח אחר.

לאחר חיבור החשבון העסקי, אישורו ובדיקת Preview, ניתן לבצע Update ידני. `EnableUpdates.command` מבקש אישור להפעלת החלפת חוברות ודיווח בקבוצה, בודק את אישור החשבון ואת הרשאת ה־API ומפעיל את התזמון. `DisableSchedule.command` עוצר את התזמון. התוכנה אינה דורשת חשבון ChatGPT או קרדיטים של OpenAI.


## ימים ושעות מהאתר — מנהלי־על בלבד

בדף עדכון חוברות אפשר להוסיף יום ושעה נפרדים לכל בדיקה (שעון ישראל). שמרו שינויים: מחשב פעיל ומחובר יקבל אותם בתוך כחמש דקות. רעננו את אזור החיבורים כדי לראות אישור סנכרון. השמירה חלה רק על מועדים עתידיים ואינה מפעילה מחשב שתזמונו מושבת. התזמון משותף למחשבי בעל החוברות שנבחר; מפעילים מחשב אחד בלבד לכל אינטגרציה. תקלה בקבלת ההגדרות עוצרת את ההרצה כדי לא לפעול לפי תזמון ישן; פרטי הסנכרון מופיעים ב־Status.command. מחשב כבוי/ישן אינו יכול להסתנכרן.

פורמט מומלץ: `שם המלון - עיר או אזור - DD.MM.YYYY.pdf`, עם תאריך תחילת התוכנית. לדוגמה: `לאונרדו פלאזה - ים המלח - 20.09.2026.pdf`. כינויים קיימים ממשיכים לעבוד; אי־ודאות או כפילות נעצרות לבדיקה. שם המקור נשמר בדוח לצד שם החוויה.
